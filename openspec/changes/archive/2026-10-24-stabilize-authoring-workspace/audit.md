# Oleafly / HiveTeX authoring audit

Audit date: 2026-10-21. HiveTeX inspected at `2a8d2edbccd612140d06af4dbe365552c9f7e07f`; Oleafly at `4081ac429314160bc4d36a3801771e3e0ba0261f`. The pre-existing untracked `BUGS.md` and `__conntests.txt` were left untouched. Findings below distinguish source observations, user reports and hypotheses. This is an authoring/workspace audit, not a full security or feature-parity audit.

## Evidence and verification limits

- Read the current implementations, existing specs, relevant tests, CI configuration and the official Oleafly workspace screenshot. Inspected HiveTeX's checked-in `docs/images/workspace-light.png`; it is historical documentation, not proof of the current runtime appearance.
- `pnpm --filter @hivetex/compile exec vitest run test/local.test.ts`: **12/12 passed**. These test scheduling, snapshots, failures and isolation using controlled engines; they do not prove installed LaTeX or actual editor geometry works.
- Browser verification and its outcome are recorded in the verification section below. No production project was modified. Oleafly's native app and its test suite were not run.
- `e2e/helpers.ts:newUser` enables `hivetex.fakeEngine` by default. `fake-engine.ts` draws source text into a PDF. A rendered canvas in those tests does not prove that LaTeX was compiled.
- The checked-in HiveTeX screenshot visibly contains source commands in the preview, consistent with that fake engine. `e2e/screenshots.spec.ts` allows this fallback. Future product screenshots must use an actual compiled document.

## Visual direction and review sheet

Target composition: a single compact project header (back/name/role, collaborators, Share, Recompile with schedule, Download, More); a restrained activity rail; a clearly titled side panel; editor file identity and compact formatting row; balanced source/PDF panes; a short status summary with detailed popovers. Use one border per structural boundary, subtle selected rows, consistent icon sizes and existing 11–24 px editor preferences. Keep the current 1100 px responsive contract and focus mode.

Review the same article/report fixture in light/dark at 1440x900, 1280x800 and 1024x768; include long file/project/user names, no compiler, first package download, failing build with previous PDF, stale PDF during typing, offline edits and two collaborators. Browser zoom/text enlargement at 125% and 150% must preserve actionable controls. Compare screenshots together with geometric/focus assertions; a visually tidy but unreachable action fails acceptance.

## Decisions and assumptions

- Default scheduling remains automatic after changes. Proposed settings add Periodic (30 seconds by default; validated 5–300 seconds) and Manual. Both automatic modes build only changed/invalidated inputs, run locally and avoid overlapping builds. This is a planning assumption pending review of the user's optional preference question.
- Visual alignment means interaction hierarchy and finish, while preserving HiveTeX branding, source compatibility, access rules and local-only compilation. No cross-project migration is needed.
- Editor misalignment and duplicate tray instances need current-runtime reproductions; the plan must not claim their causes are known. The reproduction tasks specify exact stress cases and require an evidence-backed outcome.
- Basic template compilation is a release condition. The exact WASM package distribution decision depends on replaying the article/report failures with recorded engine and package versions; this is a bounded compiler compatibility investigation, not an open-ended rewrite.
