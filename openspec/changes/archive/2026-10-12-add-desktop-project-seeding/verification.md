#### Relayed content

- 4.63 commands per relayed envelope (publish, recipient delivery, sender and recipient presence checks, budget grants amortised over four envelopes).
- 1 MiB of payload = 128 envelopes including ACKs = **~592 Redis commands** plus the encoded bytes on ingress, backend and egress (debited 3x).
- The shipped profile cap (100,000 envelopes / 30 days) alone allows ~462,500 commands.

#### Assumptions and limits of this report

- Upstash counts every command, EVAL included, and each pub/sub delivery; the in-memory backend reproduces the command sequence, not network latency.
- One WebSocket per project and device; the socket is replaced every 300 s (vercel.json). Vercel Active CPU and memory time are not measured here.
- Ticket refreshes, joins of other peers, peer exchange, project API calls and the other application traffic come on top.
- Co-location depends on the platform routing sockets of one device to one instance; it is not guaranteed. Size for the distributed column.

### Conclusion and configured headroom

- Four always-on idle seed projects of a single device need ~0.5-0.8 M Redis commands per 30 days, mostly from the 300 s socket rotation (12.3 commands each). That alone reaches or exceeds the Upstash free tier (500 k), before any user's interactive traffic or relayed content.
- The shipped relay cap (100,000 envelopes) costs ~500 k commands by itself. The relay profile is therefore **off by default** and startup refuses `APPLICATION_RELAY=1` unless `RELAY_PROVIDER_COMMANDS` and the measured `RELAY_BASELINE_COMMANDS` leave room for `RELAY_ENVELOPES` x 5 commands (relay-budget.test.ts).
- Consequence for desktop seeding defaults (D8/D13, tasks 8.6/12.3): on a free-tier deployment background seeding must be budgeted per deployment, not only per device; sessions beyond the budget are queued as unavailable seeds. Recorded as an open sizing limitation.
